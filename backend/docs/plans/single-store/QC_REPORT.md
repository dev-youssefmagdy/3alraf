### Security review (diff) — PASS
- **Admin routes:** every `admin.*` route has `Authenticate:admin` (login routes `guest:admin`); every non-ERP/non-validate route has `Authorize:<perm>` or is auth-only exactly as on main (dashboard, barcode, notifications, locale, logout, broadcasting auth, signed private files). ERP routes check in-controller (`ErpController::allow`), incl. the new anomalies page/export (`erp.audit.view`). Settings → General `general_settings.view/edit`; AI platform card `can:ai_platform.edit` (controller middleware).
- **Guard merge:** guards `web` (customers), `affiliate`, `admin`, Sanctum `customer_api`/`affiliate_api`; separate providers/tables; no admin route accepts another guard. Broadcast channels `App.Models.Admin.{id}`, `whatsapp`, `whatsapp-chat` on guard `admin` with `is_active` + permission. `Gate::before` super-admin unchanged from main.
- **LegacyHostRedirect:** acts only when the Host ends with `.APP_HOST` (TrustHosts also limits hosts to `APP_HOST` + subdomains); the redirect target is always `config('app.url')` + path + query, never the request host → no Host-header open redirect (a `//evil` path stays on APP_URL). `webhooks/*`, `api/*` pass through the normal stack (CSRF exclusion still only `webhooks/*`, auth middleware unchanged).
- **HMAC:** integration API (`IntegrationIpAllowlist` + `IntegrationAuth`, `SignatureService` untouched) and `internal/whatsapp/events` signature checks unchanged; payment webhooks verified per provider, URLs built from `APP_URL`.
- **Mass assignment:** `Product::$fillable` has the price fields, but every writer goes through validated DTOs (`ProductService::payload`, `CatalogService`, `StockLedger::syncListingCost` forceFill of `cost`); no `->fill($request->all())`. `CatalogItemRequest`/`ProductRequest` validate numeric ≥ 0, `sale_price < price`, variants `exists:product_variants,id,product_id,{id}`. `is_super_admin` only via `SuperAdminProvisioner` (test kept).
- **Unique constraints:** script over INVENTORY §C.2 vs `information_schema.statistics` of `3alraf`: **117/117** planned UNIQUE/INDEX replacements present (the only "missing" one, `tenant_products UNIQUE(product_id)`, is moot — merged into `products` PK).
- **Encrypted settings:** see F2 (fixed). `Setting::$hidden = ['value']`.
- **otp_exempt:** editable only when the actor holds a system role (`super-admin` or `owner`) — same rule as main (`tenant-owner` / central `super-admin`); a super admin's row can only be edited by a super admin. Not settable by any other admin form (`AdminUserRequest` `sometimes|boolean`, ignored for non-system actors).

### Correctness review — PASS (after F1)
- **Conversion migration** (640 lines): MySQL guard, aborts on >1 tenant (soft-deleted included), `down()` throws, idempotent (`settings` exists → skip). Listing merge SQL (`is_active = master AND listing`, unlisted → inactive + NULL price) matches §1.13; `TenantProduct` had no soft deletes, so no hidden listings. Covered by `ConversionMigrationTest`.
- **Pricing:** `PriceResolver::item()` is a 1:1 port (variant with own price uses its own sale price; cost variant → product; inactive/unpriced/trashed → null), as CALCULATIONS.md line 7.
- **`JournalService::lockLedger()`:** `SELECT … FOR UPDATE` on one `settings` row, created with `insertOrIgnore` then re-locked; used for numbering, `exclusive()` and profit-distribution runs (same serialisation as the old tenant-row lock). The row decodes as `null` in `setting()`, never written through `Setting::put`.
- **StockLedger:** branch existence checked before INSERT IGNORE (QA fix), weighted cost synced to `products`/`product_variants`.
- **Payments / QR / affiliate links:** return + webhook URLs from `config('app.url')`; QR/affiliate URLs `url('/{default_locale}/product/{slug}')`; real DB QR rows already rebuilt (Phase 5).
- **Scheduler / jobs:** 20 events; queued jobs carry no tenant id (stale ones deleted by the migration). See F6/F7.

### Performance spot checks — PASS
Query counts on the copy DB (one request each, array cache): `admin/catalog/datatable` (50 rows) **9**, `admin/products/datatable` (50 rows) **4**, `admin/catalog` 8, `/ar` 29, `/en` 27, `api/v1/home` 22, `api/v1/catalog` 6 — no per-row repetition (N+1). Storefront home runs `select id from products where is_active and price is not null` 4× (one per rail, `ProductListResolver::resolve`) — same pattern as main (`tenant_products` pluck), cached rails (`rank.*`) unaffected. Indexes: `products_is_active_id_index (is_active, id)` + `products_gift_suitable_index` added by the migration; price filter is a residual on that index (no separate price index needed at 1.2k rows).
