## 1. Decisions (team lead, binding for all agents)

1. **AI removal** = delete the whole in-panel AI module (routes, controllers, services, models, views, lang, config, middleware, settings switch, nav, tests, scheduled commands) and every AI call inside other features (replace with deterministic logic). A migration drops the `ai_*` tables. Claude now works **only from outside** via the MCP server (Claude Pro connector).
2. **n8n removal** = delete the whole Growth system and every n8n workflow/endpoint EXCEPT the gift-finder flow. **n8n itself stays and must run on its own subdomain** (`n8n.3alraf.loc` locally, `n8n.3alraf.com` in production, no Docker). The `/api/integration/v1` API is reduced to: `ping`, `health` and gift-finder endpoints (HMAC + bearer auth, `IntegrationClient` kept, client management page moves to the marketer panel). The gift-finder n8n flow = scheduled workflow(s) that read gift-finder stats + products/bundles missing gift tags + upcoming occasions and notify the owner (and a failed-workflow handler). The gift finder itself, which is extracted out of Growth into a standalone `GiftFinder` module (no growth flag). Shared bits used by non-growth code (e.g. `orders.attribution`, bundle A/B variant attribution on storefront, supplier prices, ambassador payout ledger in CALCULATIONS) must be checked: keep what live store code needs, remove the rest. A migration drops orphan growth tables. MCP.md's n8n parts (Phase 7, §25) are **out of scope** by owner decision; scheduled reports use the Laravel scheduler instead where cheap.
3. **Marketer panel** = new panel at `/marketer` (route names `marketer.*`, same `admin` guard, own layout + RTL nav, every page permission-gated with `marketing.*` permissions, new role `marketer`). It hosts all MCP.md modules (Suggestions Center + all suggestion types, approvals & execution log, product social-media library, seasonal themes, SEO suggestions, blog suggestions, Meta campaign drafts & approval, marketing analytics, MCP access tokens & audit log, gift finder admin) and a "Marketing tools" group with links to the existing marketing modules (banners/slider, coupons, flash sales, bundles, blog, SEO settings, affiliates).
4. **Integration architecture**: Laravel = source of truth. `/api/internal/marketing/*` (read + "create pending suggestion" only), Sanctum-style hashed service tokens managed in the marketer panel, scopes, rate limit, request log without PII. MCP server = separate Node/TS project `mcp-server/` in this repo (Streamable HTTP, official `@modelcontextprotocol/sdk`, Zod), it only calls the Laravel internal API. **Meta Marketing API client lives in Laravel** (tokens never leave Laravel; the approval page is in Laravel), MCP exposes read + draft tools only; publishing to Meta (always PAUSED) is a button in the marketer panel after approval tied to a content hash.
5. Claude can never approve/apply; approval & apply are dashboard-only actions guarded by permissions.
6. **Product video**: products get videos (upload mp4/webm or YouTube/Vimeo URL is NOT required — upload only, private? no: public, product gallery). Storefront product page main slider mixes images + videos ordered by sort_order; the active video slide autoplays muted+inline and pauses when it leaves; thumbnails show a play badge. Social-media library media stays private and never appears here.
7. Docs: deliverables listed in MCP.md §14/§29 go to `backend/docs/marketing/` (combined where sensible), plus root `implementation_steps_of_mcp.docx` for external setup.
